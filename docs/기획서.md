# PhotoAI Organizer 기획서

**AI 기반 사진 파일명 자동 생성 및 정리 프로그램** · 문서 버전 V1.3 (구현 결과 반영)

> 표기: **[변경]** 초안에서 바꾼 내용, **[추가]** 초안에 없던 내용, **[확인필요]** 결정이 필요한 항목

---

## 1. 개요

### 목표
사진의 EXIF 촬영일, GPS, AI 분석 결과로 사람이 알아볼 수 있는 파일명을 만들고, 폴더로 정리하는 Windows 프로그램. 수천~수만 장을 최소한의 조작으로 정리하는 것이 목표다.

### 예시
| | 파일명 |
|---|---|
| 변경 전 | `IMG_20210216_191725.jpg` |
| 변경 후 | `20210216_191725_연수구송도동_산책중.jpg` |

### 사용자 흐름
```
원본 폴더 선택 → [분석 시작] → 자동 파일명 생성 → 자동 정리 → 정리완료
```

## 2. 기본 원칙

1. **확인 가능한 정보만 쓴다.** 정보가 없으면 해당 항목을 파일명에서 뺀다.
   - 촬영일 없음 → 날짜 제외 / GPS 없음 → 장소 제외 / AI 실패 → 설명어 제외
2. **추정 금지.** 파일 생성일, 수정일, AI가 추정한 촬영일은 쓰지 않는다.
3. **실패한 파일은 원본 위치에 그대로 둔다.**
4. **[변경] 원본은 검증 후에만 제거한다.** 초안은 "이동 후 원본 제거"였으나, 복사 → 크기·해시 검증 → 원본 삭제 순서로 처리한다. 같은 드라이브면 이동(rename)으로 처리해도 된다. 중간에 중단돼도 원본이 사라지지 않게 하기 위함이다.

## 3. 플랫폼 및 배포

- V1: Windows 전용, 포터블 `PhotoAI.exe`. 추후 설치형 `PhotoAISetup.exe`.
- **[추가]** Ollama와 비전 모델(기본 gemma3:4b)(수 GB)은 exe에 포함할 수 없다. [분석 시작] 시 Ollama 연결과 모델 설치 여부를 검사한다(`ai.diagnose`).
  - **[변경]** 없으면 사용자 동의를 받아 자동 준비한다(`ai.prepare`): 공식 `OllamaSetup.exe` 다운로드 후 `/SILENT` 설치 → `ollama serve` 실행 → 모델 `pull`. 진행 상황은 상태줄·진행바에 표시한다. 대화상자에서 "아니요"를 고르면 "AI 미사용" 모드로 계속한다.
  - 원격 Ollama URL(localhost가 아님)은 자동 설치하지 않고 "AI 없이 계속" 여부만 묻는다.
  - 확인됨: 실제 Ollama 자동 설치(`/SILENT` 포함)와 모델 자동 다운로드, AI 설명어의 파일명 반영이 동작함을 확인했다.

## 4. 처리 파이프라인

```
원본 폴더 선택 → EXIF(촬영일·GPS) → 장소명 조회 → AI 분석(선택)
→ 파일명 생성 → 중복 검사 → 정리완료 폴더로 이동 → 원본 제거
```

- **[추가]** 하위 폴더 포함 여부를 옵션으로 둔다(기본 ON). 결과 폴더가 원본 폴더 안에 있으면 재스캔에서 제외한다.
- **[추가]** 지원 형식: JPG, PNG, WEBP, **HEIC**(아이폰, pillow-heif 사용). RAW는 V1 범위 밖이며 건드리지 않는다.
- **[확인필요] 동영상(MP4, MOV):** 메타정보로 사진과 같은 규칙의 파일명 생성이 가능하다. 아래 내용을 확인하고 포함 여부를 정한다.
  - 촬영일: 컨테이너의 `creation_time`(UTC)을 로컬 시간으로 변환해 사용한다. 값이 비었거나 1904-01-01이면 "촬영일 없음"으로 처리한다.
  - GPS: 아이폰(`com.apple.quicktime.location.ISO6709`)과 안드로이드(`©xyz`) 영상에는 위치가 들어 있는 경우가 많다. 없으면 장소 제외.
  - AI: 영상 중간 지점의 프레임 1장을 뽑아 같은 방식으로 분석한다.
  - 필요 도구: `ffprobe`/`ffmpeg`(exe에 포함하면 약 80MB 증가). 해시는 대용량이므로 청크 단위로 계산한다.
  - 주의: 편집·내보내기·메신저 전송을 거친 영상은 `creation_time`이 촬영일이 아니라 변환 시각인 경우가 있다. "추정 금지" 원칙상 의심스러운 값은 분류불가로 보낼 수 있다.

| 시간 | **[추가]** 작업 완료 시 총 소요시간과 장당 평균 시간(예: `총 소요시간: 3분 12초 평균: 0.64초/장`) |

| 결과 | **[추가]** [결과] 버튼: 성공(원본 → 새 이름), 실패(파일명), 분류불가(파일명), 중복(원본 → 중복파일 폴더 이름 / 동일한 기존 파일) 목록 창. 분석이 끝나야 활성화되고, 새 분석을 시작하면 결과를 지운다 |
| 실행 | **[분석 시작]** (진행률, 취소 버튼 포함 **[추가]**), **[추가]** [마지막 작업 되돌리기], **[추가]** [종료] |

- **[추가] 취소:** [취소]를 누르면 즉시 "취소하는 중..."을 표시하고, 지금 처리 중인 사진까지 끝낸 뒤 멈춘다(파일이 반쯤 옮겨진 채로 끊기지 않게). 멈추면 "취소 완료" 알림에 처리된 장수와 되돌리기 안내를 보여 준다.
- **[추가] 종료:** [종료] 버튼은 분석 중이 아니면 바로 닫는다. 분석 중이면 확인 후 취소와 같은 방식으로 현재 사진까지 끝내고 알림 없이 닫는다. (창의 X 버튼은 바로 닫으며, 같은 안전 처리는 아직 없다.)
- **[추가] [마지막 작업 되돌리기]:** 가장 최근 작업에서 옮기거나 이름을 바꾼 파일을 이동 이력으로 원래 위치·이름으로 복원한다. 새 위치에 파일이 없거나 원래 자리에 다른 파일이 있으면 건너뛰고 개수를 알린다. 누를 때마다 한 작업씩 이전으로 거슬러 간다. 통계와 빈 폴더는 되돌리지 않는다.

- **[변경]** 장소명은 인터넷·API 키 없이 내려받아 둔 공공 행정동 경계 데이터로 구한다(7장). 키 입력란은 없다.

## 6. EXIF 정책

- 사용: `DateTimeOriginal`, GPS
- 촬영일 있음 → 정상 처리
- 촬영일 없음 → `정리완료/분류불가`로 이동 (파일명 규칙은 10장 참고)
- 날짜 형식은 `YYYYMMDD_HHMMSS`.

## 7. GPS·장소명 정책

- GPS 있음 → 공공 행정동 경계 데이터에서 좌표가 속한 행정동을 찾아 장소명으로 쓴다. GPS 없음 → 장소 제외.
- **[변경]** 외부 API를 쓰지 않는다. 키·호출 한도·좌표 외부 전송 문제가 없고, 좌표가 속한 행정동을 직접 찾으므로 동 경계 오류도 없다.
- **[확정] 데이터:** GitHub `vuski/admdongkor`의 행정동 경계(`HangJeongDong_ver20261001.geojson`, MIT, 행정동 3,559개, WGS84, 약 35MB). 코드에 URL과 SHA-256을 고정하고, 해시가 다르면 저장하지 않는다. 갱신하려면 URL·해시를 같이 바꾼다.
- **[변경] 받기 규칙:** 데이터가 DB에 없으면 [분석 시작]을 누를 때 묻지 않고 반드시 내려받는다(약 35MB를 받아 SQLite `regions` 테이블, 약 18MB에 저장). 받지 못하면 분석을 시작하지 않고 오류를 알린다. 데이터가 있으면 바로 분석하고, "행정구역 데이터 다시 받기"를 체크한 경우에만 [분석 시작] 때 새로 받은 뒤 분석한다(체크는 자동으로 해제). 다시 받기가 실패하면 기존 데이터로 계속한다. 이후에는 인터넷 없이 동작한다.
- **조회 방식:** 사진 좌표가 경계 사각형 안에 드는 후보만 추려 점-다각형 판정(구멍 처리 포함)을 한다. 사진당 약 1ms. 어느 행정동에도 없으면(바다 등) 장소를 생략한다.
- 장소명은 POI(건물·공원 이름)가 아니라 **주소명**: `시군구` + `동`을 이어 붙이고 시·도는 뺀다. 최대 10자(넘으면 동을 남기고 앞을 줄임). 행정동 이름의 가운뎃점(`·`)은 `.`으로 바꾼다. 예: `연수구송도1동`, `미추홀구도화2.3동`.
  - **[주의]** 행정동 기준이라 법정동 이름(`송도동`)이 아니라 `송도1동`~`송도4동`처럼 나온다.
- 설정 화면에 외부로 좌표를 보낸다는 안내는 필요 없다(좌표가 PC 밖으로 나가지 않음).

## 8. AI 분석 정책

- 사용: Ollama + Gemma 3 4B(기본값, 설정에서 변경 가능; 이전 기본값은 Qwen2.5-VL). 분석 항목은 분위기, 행동, 사진 특징 → 결과는 짧은 한 단어(설명어)로 요약. 예: 산책중, 가족사진, 일몰풍경, 반려견, 커피사진.
- AI 미사용 → 메타정보(날짜·장소)만으로 이름 생성. 예: `20210216_191725_연수구송도동.jpg`
- **[추가]** 프롬프트는 사진에 사람이 있으면 사람 중심(가족사진, 아이웃음 등), 없을 때만 사물·동물·풍경을 말하게 한다.
- **[추가] Ollama 자동 실행:** AI 사용이 켜져 있고 이 PC에 Ollama가 설치돼 있는데 꺼져 있으면, 창이 열릴 때 백그라운드로 실행하고 [분석 시작] 때도 묻지 않고 실행한다(설치·모델 다운로드만 동의를 받는다). 서버가 꺼져 있어도 모델 폴더(`~/.ollama/models/manifests`, `OLLAMA_MODELS` 반영)를 읽어 설치 여부를 표시한다.
- **[추가] 모델 미리 올리기:** 분석을 시작할 때 모델을 먼저 메모리에 올리고(상태줄 "AI 모델을 불러오는 중..."), 분석 사이에는 모델을 30분 유지(`keep_alive`)한다. 한동안 쉬면 Ollama가 모델을 내려서 첫 분석이 매우 느려지던 문제 때문이다.
- **[변경]** AI 응답 시간 제한을 두지 않는다(느린 PC에서 제한 때문에 실패하던 문제). 대신 서버 연결 오류로 2장 연속 실패하면 작업을 멈추고 알린다.
- AI 실패(빈 응답, 규칙 위반, 연결 오류) → 설명어 없이 진행. **[추가]** 1회 재시도 후 실패 처리.
- **[추가]** AI 출력은 9장 규칙으로 후처리하고 규칙을 만족하지 못하면 실패로 본다.
- **[추가] 선택 가능한 AI 모델 10개** (`ai.MODELS`, 자동 다운로드 허용 목록을 겸함): `gemma3:4b`(기본), `gemma3n:e2b`, `gemma3n:e4b`, `qwen2.5vl:3b`, `qwen2.5vl:7b`, `qwen3-vl:4b`, `llava:7b`, `minicpm-v:8b`, `moondream`, `granite3.2-vision`. 크기·속도·한국어 품질은 모델마다 다르므로 같은 사진으로 비교한다. 목록 밖 모델은 자동 설치하지 않는다(직접 `ollama pull`).
- 참고: 설명어는 AI의 해석이므로 "확인 가능한 정보만" 원칙의 예외다. 선택 기능이고 사용자가 끌 수 있으므로 허용한다.

## 9. 설명어(초안의 "상태명") 규칙

- 최대 10자, 공백 금지, 특수문자 금지(Windows 금지문자 `\ / : * ? " < > |` 포함).
- **[변경]** 용어를 "상태명"에서 **설명어**로 바꾼다. (분위기·행동·특징을 모두 포함하므로)

## 10. 파일명 규칙

| 촬영일 | GPS | AI | 파일명 | 저장 위치 |
|---|---|---|---|---|
| O | O | O | `날짜_장소_설명어.jpg` | 정리완료 |
| O | O | X | `날짜_장소.jpg` | 정리완료 |
| O | X | O | `날짜_설명어.jpg` | 정리완료 |
| O | X | X | `날짜.jpg` | 정리완료 |
| X | - | O | `원본파일명_설명어.jpg` | 정리완료/분류불가 |
| X | - | X | `원본파일명.jpg` | 정리완료/분류불가 |

- **[확인필요]** 현재 구현은 촬영일이 없으면 AI·장소 조회를 하지 않고 위 5행도 `원본파일명.jpg`로 둔다(설명어를 붙이지 않음). 5행대로 구현할지 정해야 한다.

- 예: `20210216_191725_연수구송도동_산책중.jpg`, `KakaoTalk_20240705_015802579_가족사진.jpg`
- **[추가]** 확장자는 소문자로 통일. 전체 경로가 Windows 260자를 넘으면 설명어 → 장소 순으로 줄인다.
- **[추가]** 촬영일이 없는 사진은 `원본파일명`에 이미 설명어가 붙어 있는 경우(재실행)를 중복으로 붙이지 않는다.

## 11. 중복 파일 처리

**동일 파일 검사** 체크박스 (기본 ON).

**[변경] 정리된 파일 색인 + 체크섬 비교** (검사 ON일 때)
1. [분석 시작] 직후, 결과 폴더 바로 아래의 **정상 분류된 파일**(`분류불가`·`중복파일` 폴더는 제외)의 메타 정보를 SQLite `file_index`에 저장한다: 경로, 크기, 수정시각, 촬영일, 위치(GPS), SHA-256. 바뀌지 않은 파일은 다시 읽지 않고, 지워졌거나 옮겨진 파일은 색인에서 지운다.
2. 새 사진(촬영일 있는 것)은 **파일명과 상관없이** 색인에서 **크기가 같은 파일**만 후보로 삼아 SHA-256을 비교한다(후보의 해시는 처음 필요할 때 계산해 저장). 같으면 `정리완료/중복파일`로 보낸다. AI·장소 조회 **전에** 판정하므로 중복 사진은 느린 AI 분석을 건너뛴다. 중복 사진은 **원본 파일명**으로 저장한다(충돌 시 `_001`).
3. 정상 분류가 끝난 파일은 메타 정보를 색인에 바로 추가한다(같은 분석 안의 중복도 잡힘).
- 촬영일·위치는 색인에 보관만 하고 판정에는 쓰지 않는다. 판정은 체크섬(크기 → SHA-256)으로 한다.
- 색인 대상이 아닌 경우(촬영일 없는 사진 → `분류불가`)는 아래 이름 규칙으로 처리한다.

**이름 규칙** (같은 이름이 생성될 때만 비교):

| 설정 | 이름 동일 + 해시 동일 | 이름 동일 + 해시 다름 |
|---|---|---|
| OFF | `파일_001.jpg`, `파일_002.jpg` … | 같음 |
| ON | `정리완료/중복파일`로 이동 | `파일_001.jpg`, `파일_002.jpg` … |

- **[추가]** 해시는 SHA-256(파일 내용). 지각적 해시(ImageHash)는 "비슷한 사진" 탐지용이므로 V6에서 쓴다.
- **[추가]** 연사처럼 촬영일(초 단위)이 같고 내용이 다른 사진은 체크섬이 달라 중복이 아니며, 이름이 같으면 `_001`이 붙는다. 편집·재저장으로 내용이 달라진 사본은 중복으로 잡히지 않는다.
